# G0 双路扭矩传感器 CAN 通讯协议（上位机插件实现说明）

本文描述 CANable 2.5 上位机 **`torque_sensor` 插件**实际收发的扭矩传感器 CAN 协议。

- 实现位置：`plugins/torque_sensor/protocol.py`（帧构造/解析）、`widget.py`（时序与 UI）、`setid.py`（站号扫描/改号）
- 原始协议来源：仓库根目录 `torque_sensor_can_protocol_zh.md`；硬件标零的 CAN 帧格式另参照参考固件 `E1_Hand_G474`（`srv_juxie_motor.c: srv_juxie_motor_zero()`）
- 适用器件：G0 双路扭矩传感器（Z 轴扭矩 `Mz`，单位 **N·m**）

---

## 1. 总线与帧约定

| 项目 | 配置 |
| :--- | :--- |
| 总线 | **Classic CAN（非 CAN FD）** |
| 波特率 | **1 Mbit/s**（不匹配时插件会提示） |
| 帧类型 | **标准帧**（11 bit 标识符） |
| 字节序 | 多字节浮点为 IEEE-754 **float32，大端**；整数按表说明 |
| 应用层校验 | 无（CRC 由 CAN 控制器负责） |
| 控制帧长度 | **DLC = 7**（`data[0..6]`） |

> 插件对 9 字节以上的 FD 帧不做任何使用；扭矩传感器面板一旦检测到主机处于 FD 模式会提示关闭。

---

## 2. 通道与 CAN ID

| 通道 | 名称 | 站号 | 主机请求 ID | 传感器响应 ID |
| :---: | :--- | :---: | :--- | :--- |
| 0 | sensor0 | 1 | `0x510` | `0x410`（新格式 + 命令应答）、`0x411`（旧格式） |
| 1 | sensor1 | 2 | `0x520` | `0x420`（新格式 + 命令应答）、`0x421`（旧格式） |

通用映射（站号 `n = 1..47`）：

```
请求 ID = 0x500 + n × 0x10        # 站号 47 → 0x7F0，站号 48 → 0x800 越界，故最大 47
响应 ID = 0x400 + n × 0x10
```

> `0x410/0x420` 同时承载**新格式测量帧**和**命令应答**，由数据区前 3 字节前缀区分（见 §4、§5）。
> 面板固定监控站号 1、2 两路；站号被改到其它值后需改回 1/2 才能被读取（可用「扫描/设置 ID」确认）。

---

## 3. 主机控制帧（DLC = 7，标准帧）

数据区统一格式：

```
data[0] = 0x10          写/请求命令标志
data[1] = 寄存器高字节
data[2] = 寄存器低字节
data[3..6] = float32 大端值
```

| 操作 | 寄存器 | 值 | 完整数据区（十六进制） | 发往 |
| :--- | :---: | ---: | :--- | :--- |
| 停止主动上报 | `0x5003` | `0.0` | `10 50 03 00 00 00 00` | 请求 ID |
| 设置采样率 | `0x5002` | Hz（默认 `1000.0`） | `10 50 02 44 7A 00 00`（1000 Hz） | 请求 ID |
| 开启主动上报 | `0x5003` | `255.0` | `10 50 03 43 7F 00 00` | 请求 ID |
| 硬件标零 | `0x4604` | `1.0` | `10 46 04 3F 80 00 00` | 请求 ID |

参考常量：`1.0 = 3F 80 00 00`、`255.0 = 43 7F 00 00`、`1000.0 = 44 7A 00 00`。

---

## 4. 命令应答匹配

命令应答使用对应通道的**新格式响应 ID**（sensor0 → `0x410`，sensor1 → `0x420`）。插件判定规则：

1. `DLC ≥ 3`；
2. 数据区前 3 字节等于下表前缀。

| 应答类型 | 前缀 | 说明 |
| :--- | :--- | :--- |
| 采样率写入应答 | `10 50 02` | 不校验后续数值 |
| 上报模式写入应答 | `10 50 03` | 开启/停止上报共用 |
| 硬件标零应答 | `10 46 04` | 需 `data[3..6]` 为 `3F 80 00 00` 才算成功（见 §7） |

- 插件对普通写入命令等待应答 **1.5 s**，超时后状态显示「应答超时」。
- **开启上报**时，若先收到格式正确的新格式测量帧，也视为上报已启动。
- 由于 `0x410/0x420` 复用，收到不匹配任何前缀的帧会按测量帧继续解析（见 §5）。

## 5. 扭矩测量帧（单位 N·m）

### 5.1 新格式（`0x410` / `0x420`）

| 字段 | 长度 | 说明 |
| :--- | ---: | :--- |
| CAN ID | — | sensor0 `0x410`；sensor1 `0x420` |
| DLC | ≥ 7 | 不足 7 字节判为无效帧 |
| `data[0..2]` | 3 | 固定前缀 `04 00 00` |
| `data[3..6]` | 4 | 大端 float32 扭矩值（N·m） |

示例：`ID=0x410, DLC=7, data=04 00 00 3F 80 00 00` → sensor0 `+1.0 N·m`

### 5.2 旧格式（`0x411` / `0x421`）

| 字段 | 长度 | 说明 |
| :--- | ---: | :--- |
| CAN ID | — | sensor0 `0x411`；sensor1 `0x421` |
| DLC | ≥ 4 | 不足 4 字节判为无效帧 |
| `data[0..3]` | 4 | 大端 float32 扭矩值（N·m） |

示例：`ID=0x421, DLC=4, data=BF 80 00 00` → sensor1 `−1.0 N·m`

### 5.3 无效帧判定

- DLC 不足上述要求；
- float32 不是有限数（NaN / Inf）；
- 新格式 ID 上既不是应答前缀、也不是 `04 00 00` 前缀。

满足任一条即计入该通道"无效帧"，不更新扭矩值。面板同时显示有效帧数与无效帧数。

## 6. 上报初始化流程（插件「初始化上报」/ 连接后自动初始化）

默认采样率 **1000 Hz**，`auto_init` 默认开启。

```
① 对两路发送「停止主动上报」            (10 50 03 00 00 00 00)
② 等待 30 ms
③ 对两路发送「设置采样率」              (10 50 02 <float32 Hz>)
④ 等待 30 ms
⑤ 对两路发送「开启主动上报」            (10 50 03 43 7F 00 00)
```

- 面板「设置采样率」只执行 ③（对两路）。
- 「全部开始 / 全部停止」直接发 ⑤ / ①。
- 收到测量帧或上报模式应答即认为该通道进入"上报中"。

---

## 7. 硬件标零（CAN 帧）

硬件标零是**真实 CAN 命令**，让传感器把当前机械位置设为零点：

```
发送：10 46 04 3F 80 00 00      → 目标通道请求 ID（0x510 / 0x520）
应答：10 46 04 3F 80 00 00      → 该通道响应 ID（0x410 / 0x420），DLC ≥ 7
```

插件执行序列（单路）：

1. 记录当前正在上报的通道；
2. 对这些通道发送「停止主动上报」（降噪）；
3. 60 ms 后向目标通道发送硬件标零命令；
4. 等待应答，超时 **700 ms**；期间的测量帧与其它帧被跳过；
5. 收到 `10 46 04 …` 且值为 `1.0` → 判定成功；
6. 成功后清除该路**软件零点**并写回配置；
7. 恢复步骤 1 记录的通道上报。

失败/超时提示"硬件标零超时（未收到应答）"，不会静默修改零点。

---

## 8. 软件标零（应用层，不发 CAN 帧）

软件标零只在上位机侧做偏移，**不向传感器发送任何帧**：

```
offset = −raw_mz
reported = raw_mz + offset
```

- 要求该通道当前已有有效数据，否则拒绝并提示"该通道暂无有效数据"。
- 偏移按通道分别持久化（`plugin.torque_sensor.offset0/1`），重启后加载。
- 「清除零点」把偏移置 0。
- 面板与波形显示的都是 `reported`（校正值）；原始值 `raw_mz` 仍单独显示。

## 9. 站号扫描与设置 ID（`0x500+ID×0x10` / `0x400+ID×0x10`）

用于确认/修改传感器站号（站号决定请求与响应 ID）。该操作在**独占任务**中执行：执行期间正常收发暂停，结束后恢复。

### 9.1 扫描

- 逐个站号 `1..47` 发送 **DLC = 8** 的查询帧：

```
CAN ID = 0x500 + n × 0x10
data   = 04 00 00 00 00 00 00 00
```

- 每个站号等待 **50 ms**，统计匹配应答。
- 匹配条件：标准帧、`CAN ID = 0x400 + n × 0x10`、`DLC 7 或 8`、`data[0..2] = 04 00 00`、`data[3..6]` 为有限 float32。
- **仅当恰好一个站号应答且该站号只回一次**时才允许后续改号；否则拒绝（提示响应站号数/多回复）。

### 9.2 设置 ID

- 向**当前站号**发 **DLC = 7** 的改号帧：

```
CAN ID = 0x500 + current × 0x10
data   = 10 00 90 + float32_be(target)      # 例：目标 2 → 10 00 90 40 00 00 00
```

- 等待最多 **1 s**：旧地址或新地址返回 `10 00 90 3F 80 00 00` 视为成功。
- 成功后传感器改用新站号；超时提示"地址可能已改变，请重新扫描确认，不要盲目重发"。
- 扫描前会先向站号 1、2 发送「停止主动上报」以降噪（失败不影响扫描）。

> ⚠️ 面板的监控通道固定为站号 1、2；把传感器改到其它站号后，需改回 1/2 才能继续读取。

## 11. 注意事项

1. **必须 Classic CAN + 1 Mbit/s**；启用 CAN FD 或其它波特率都会导致无数据（插件会提示）。
2. 控制帧固定 **DLC = 7**，勿把结构体里未发送的第 8 字节当成线上数据。
3. `0x410/0x420` 混载测量与应答，判断时**先看前缀**（`10 xx xx` = 应答，`04 00 00` = 新格式测量）。
4. 硬件标零会改变位置参考，请在目标机械位置且电机静止时执行。
5. 站号最大 **47**（再大则请求 ID 超过 11 bit 范围 0x7FF）。
6. 软/硬件标零是两件事：软件标零只改上位机显示，硬件标零才真正写入传感器。
